# ADR-004: 部署与合规

- 状态：Proposed（待需求方/政数部门确认）
- 日期：2026-11-06
- 决策人：项目开发者
- 相关任务：OPS-001~004、YX-001~005
- 相关文档：`docs/agent/05-architecture.md` §11/§13、`docs/agent/10-resources.md`

## 1. 背景

项目后期要接粤政易。材料显示：

- 粤政易支持 WEB 网页、移动 H5、微信小程序。
- 平台仅供处理**非密、非敏感**信息。
- 部署在互联网/单位局域网：只能作为工作台入口跳转，不能对接省政务外网 API/SSO。
- 部署在政务外网：可申请网络策略，对接 SSO/可见人员/待办等。
- 上线需要功能测试报告、安全测试报告、等保（正文二级/上线资料三级，表述冲突）、信创符合性测试、密码评估等。
- **暂无粤政易测试账号**，需向省申请；外部周期不可控。
- 市云平台可提供少量信创云资源；高 CPU/存储/数据库需自行解决。

同时，MVP 需要尽快做出可演示版本，不能被合规审批阻塞。

## 2. 决策

采用**两阶段部署 + 合规预留**：

### 阶段 1：11.12 初步 demo（现在）

- **本地进程**：FastAPI + SQLite + Vite + 原生微信小程序；**不强制 Docker**（当前机器未安装 Docker）。
- 如需公网 demo：一台服务器 + Nginx + HTTPS + 域名；小程序配置合法域名。
- 本地账号/JWT 或测试号/模拟登录；不接粤政易 SSO。
- LLM 用 **DeepSeek API**（OpenAI 兼容）；Key 只在服务端。
- 演示数据明确标注；不把演示数据当真实统计。
- 11.12 后再做 Docker Compose + PostgreSQL 生产部署。

### 阶段 2：粤政易/生产（后置）

- 部署到政务外网/省政务云（或需求方指定环境）。
- 接入粤政易工作台入口；如需 SSO/用户信息/待办，申请网络策略与接入参数。
- LLM 切私有化/政务云合规模型（vLLM/Ollama/指定模型）。
- 数据库按需求方要求适配（PostgreSQL/金仓/达梦/MySQL）。
- 准备功能测试/安全测试/等保/信创/密评材料；按政数部门要求整改。
- 不承诺上线日期；只承诺开发侧准备度。

### 架构预留

| 预留 | 做法 |
|---|---|
| SSO | `AuthProvider` 接口；本地账号可回退；不在业务代码写死登录方式 |
| 网络 | API 基址/域名/静态资源可配置；不依赖公网 CDN/外部服务 |
| 数据库 | SQLAlchemy 可移植类型；避免 PG 特有语法；Alembic 迁移可复用 |
| CPU/OS | Docker 多架构（amd64/arm64）；纯 Python/Node 依赖；避免原生扩展 |
| LLM | Provider 抽象；OpenAI 兼容；可关闭/降级 |
| 合规 | 审计日志、RBAC、密钥管理、HTTPS、备份从 MVP 就做 |

## 3. 后果

### 正面

- MVP 不被外部审批阻塞；可以尽早验证数据/图表/AI 价值。
- 后期迁移有明确路径，不用重写业务。
- 合规材料可以提前准备，减少上线风险。
- 数据/模型/网络均可替换，降低供应商锁定。

### 负面/代价

- 两套部署配置需要维护。
- SSO 后置意味着后期要改认证/用户映射。
- 政务外网/国产库/私有化 LLM 可能带来额外适配工作。
- 不能对外宣称“已过等保/已信创适配”，只能写“按要求设计/待测评”。

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| 粤政易要求本期上线 | 提前确认 Q-05；若必须，范围砍到最小并接受外部排期 |
| 等保级别升级到三级 | 按三级控制预留；预算/整改时间另计 |
| 国产库不兼容 | 早期 spike；必要时换库/改 SQL |
| 私有化 LLM 资源不足 | 评估小模型/CPU 推理；或申请合规 API |
| 网络策略/测试账号拖延 | 需求方牵头申请；开发侧准备材料清单 |

## 4. 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| 直接上政务外网开发 | 接近生产；SSO 可用 | 开发/调试不便；账号/网络审批慢 | 会阻塞 MVP |
| 只做互联网，不做粤政易 | 最简单 | 不满足后期需求 | 需求明确要接 |
| 只做粤政易 H5，不做微信小程序 | 合规路径清晰 | 不满足“小程序”需求；公众入口缺失 | 需求要小程序 |
| 使用粤治慧数据能力 | 合规/数据共享 | 依赖平台/接口；当前无资料 | 作为 P1 评估，不作为前提 |
| 全部私有化从第一天开始 | 合规最稳 | 成本/算力/运维高；MVP 慢 | 先用 API 验证价值 |

## 5. 实施要点

1. `deploy/docker-compose.yml`：api + db + nginx；`.env.example` 不含真实密钥。
2. Nginx：`/api`、`/admin`、`/h5`；HTTPS；CORS 白名单。
3. 小程序：HTTPS 域名、业务域名白名单、隐私协议（如收集信息）。
4. 配置：`APP_ENV`、`DATABASE_URL`、`LLM_*`、`AUTH_PROVIDER`、`CORS_ORIGINS`。
5. 健康检查：`/health`、`/ready`；容器 healthcheck。
6. 备份：每日数据库备份；恢复演练。
7. 合规清单：功能测试、安全测试、等保、信创、密评、备案、可信域名、图标、友好页。
8. 不把“等保二级/三级”写死；等政数部门书面确认。

## 6. 复审条件

- 需求方确认粤政易必须本期上线 → 重排路线，合规前置。
- 数据被认定为敏感/涉密 → 停止公有云 LLM，改私有化/本地；重新评估粤政易准入。
- 等保级别确认为三级 → 追加安全整改/测评预算。
- 要求国产数据库/ARM64 → 追加适配 spike 与测试。
- 市云平台资源不足/无法提供域名 → 改演示方案。
