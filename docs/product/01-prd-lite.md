# 01 · 一页纸 PRD（PRD-lite）

## 1. 问题

揭东区的区/镇街/村居数据以 Excel 模板收集，存在：

1. **存不住**：没有统一数据库，版本分散，历史难追溯。
2. **查得慢**：想知道某区域某指标，要翻表、对口径、再手工做图。
3. **看不懂**：缺少移动端浏览、排名、对比、图表。
4. **问不出**：没有自然语言入口，非数据人员难自助获取信息。
5. **上不了台**：后期要接粤政易，涉及等保/信创/网络/材料，不能临时抱佛脚。

## 2. 用户（待确认）

| 用户 | 核心诉求 | 优先级 |
|---|---|---|
| 数据管理员（区/镇街） | 快速导入、校验、修订、可追溯 | P0 |
| 公职人员 | 手机查本区/本镇指标、对比、汇报 | P0 |
| 领导/决策者 | 一屏看总览、排名、异常；复用统一页面，不单独开发模式 | P1 |
| 公众 | 了解揭东区情/公开数据 | P1/待确认 |
| AI 问答使用者 | 用一句话拿到数据+图 | P0 |

## 3. 价值主张

> **揭东数据，一查就有；问一句，就能出图。**

- 数据从“Excel 文件”变成“可查询、可审计的数据底座”。
- 从“找人要数”变成“自己查、自己问”。
- 从“手工做图”变成“选指标/说一句话就出图”。
- 从“通用聊天机器人”变成“有数据依据、可核对的政务数据助手”。

## 4. 核心闭环

```text
数据管理员导入/修订
      ↓
数据底座（区域 × 指标 × 年份）
      ↓
移动端浏览：区域 → 指标 → 图表
      ↓
AI 问答：问题 → 工具查询 → 答案 + 图表 + 引用
      ↓
反馈/纠错 → 数据修订 → 再导入
```

## 5. 范围

### P0（MVP）

1. **数据底座**：区域、指标、数据值、来源、审计。
2. **Excel 导入**：按原始模板；校验；错误报告；重复导入更新。
3. **后台最小能力**：登录、数据列表/编辑、导入、审计。
4. **移动端浏览**：首页、区域树、区域详情、指标详情、基础图表。
5. **AI 问答**：数值查询、排名、对比、区域画像；答案带引用和 ChartSpec。
6. **部署**：本地/演示环境；种子数据；健康检查。
7. **安全底线**：服务端 LLM Key、JWT、RBAC、审计、输入校验。

### P1

- 多年趋势、同比/环比、折线图。
- 排名/对比增强、收藏、导出 PNG/Excel、汇报模式。
- 地图可视化（GeoJSON）。
- 粤政易 SSO/工作台入口/友好页/图标。
- 数据审核/发布流程、更细权限。
- AI 评测看板、反馈闭环。

### P2 / 非目标

- 模型训练/微调、强化学习。
- 完整 BI 自助分析、实时数据流、物联网。
- 多租户、开放 API 平台、复杂知识图谱。
- 无认证的完全公开门户。
- LLM 直连数据库/生成 SQL/生成任意图表代码。

## 7. 成功指标

| 指标 | 目标 |
|---|---|
| 标准模板导入成功率 | ≥ 99%（干净数据） |
| 首页→指标→图表 | ≤ 3 次点击，≤ 30 秒 |
| AI 数字正确率（50 题） | ≥ 95% |
| AI 引用完整率 | 100% |
| ChartSpec 合法率 | ≥ 98% |
| 演示主路径 | 3/3 成功 |
| P0 阻塞 bug | 演示前 0 |

## 8. 关键假设

1. 数据非密/非敏感，可用于粤政易（待确认）。
2. 数据来源支持 Excel/接口/手工；真实样例待提供。
3. 首期以 2025 + 15 指标为准；后续扩展（已确认边界）。
4. 开发期用 DeepSeek API；生产可切私有化/政务云（已确认方向）。
5. **原生微信小程序**为主入口；粤政易等程序搭建完再接入（已确认）。

## 9. 不做什么

- 不做“万能聊天机器人”：只答本区数据相关问题。
- 不做“AI 自动写报表”：先做可核对的数据问答。
- 不做“数据中台”：只覆盖本项目指标。
- 不做“漂亮大屏”：先保证数据/图表正确。
- 不做“多人协作”：单管理员起步。

## 10. 验收（最小成功）

数据管理员能导入真实数据；公职人员能在手机上浏览并看到正确图表；AI 能对 50 个典型问题给出有依据的答案和可渲染图表。
