## 1. 阻塞问题详解

### Q-01 用户对象与入口

**已确认**：公职人员使用；微信小程序后续接入粤政易工作台；粤政易等程序搭建完再接入。

**为什么重要**：决定登录方式、权限、页面、部署形态、是否需要粤政易 SSO、是否需要公众访问。

**选项**：

| 方案 | 说明 | 代价 |
|---|---|---|
| A. 仅公职人员，粤政易为唯一入口 | 需政务外网 + SSO + 测试账号 | 合规周期长；开发期无法真实验证 |
| B. 公职人员用粤政易，公众用微信小程序 | 双入口；数据可见范围不同 | 两套认证/权限；内容审核 |
| C. 微信小程序为主，粤政易后续 | 开发快；先互联网演示 | 后期要补 SSO/网络/合规 |
| D. 仅 Web 后台内部使用 | 最简单 | 不满足“移动端/小程序”需求 |

**已确认方向**：公职人员；微信小程序后续接粤政易。建议先做**原生微信小程序 + 后台登录**，认证层抽象；粤政易作为后续接入。若明确要求只走粤政易且必须 SSO，再提前接入。

**剩余需要回答**：
1. 小程序是否需要登录？用什么登录（微信/手机号/粤政易）？
2. 微信小程序 AppID/主体是否已有？
3. 是否需要公众访问？（默认本期不做）

### Q-02 数据来源与更新

**已确认**：支持 Excel 导入 / 接口 / 手工录入；更新频率由使用方决定；每次导入更新一批。

**为什么重要**：决定是做“数据采集系统”还是“数据展示系统”；决定导入器、审核、更新频率、验收标准。

**选项**：

| 方案 | 说明 | 代价 |
|---|---|---|
| A. 政府提供填好的 Excel，系统导入 | 最常见；开发可控 | 需要模板/口径/更新流程 |
| B. 政府提供数据接口，系统对接 | 实时/自动 | 需要接口文档、网络、鉴权；当前材料没有 |
| C. 系统内手工录入/审核 | 适合没有现成数据 | 工作量大；需要录入界面/审核 |
| D. 混合：Excel 导入 + 手工修订 | 务实 | 需要导入 + CRUD + 审计 |

**建议**：**D**。先支持原始模板导入 + 后台单条修订 + 审计；接口对接作为 P1。

**需要回答**：
1. 真实数据现在在哪里？谁负责？
2. 能否提供填好的 Excel（哪怕一个区的样例）？
3. 更新频率：年度/季度/月度/不定期？
4. 是否有数据接口？接口文档/网络/鉴权？
5. 数据修改是否需要审核/发布？谁审批？

### Q-03 数据范围

**已确认（边界）**：当前以现有 15 指标/2025 文件为准；后续会增加数据类型，可再对接。

**为什么重要**：决定数据模型、图表类型、工作量、验收。

**现状**：模板只有 2025、15 个指标、227 个区域，数据值为空。

**需要回答**：
1. 只有 2025，还是有 2020–2025 等历史年份？（有历史才能做趋势/同比）
2. 是否只有这 15 个指标？后续会不会加？
3. 是否需要镇街/村居全量，还是先做区和镇街？
4. 是否需要地图边界（GeoJSON）？谁提供？
5. 是否需要人口/经济之外的领域（教育、医疗、农业等）？

**建议**：先按 2025 + 15 指标 + 区/镇街/村居全量；模型支持多年/扩展指标；地图后置。

### Q-04 LLM 部署与数据密级

**已确认（方向）**：初期接入 DeepSeek API；生产是否私有化待数据密级确认。

**为什么重要**：决定能否用公有云 API、成本、延迟、合规、是否需要私有化。

**需要回答**：
1. 数据是否非密/非敏感？是否允许发送到公有云大模型？
2. 是否要求私有化部署（政务云/本地 GPU）？有无 GPU/预算？
3. 是否有指定模型（DeepSeek/Qwen/GLM/文心/自研）？
4. 是否有内容安全/备案/审计要求？
5. 每月可接受的调用成本/延迟？

**建议**：开发期用 DeepSeek/兼容 API；生产按密级切换 vLLM/Ollama/政务云模型。所有调用服务端、可关闭、可审计。

### Q-05 粤政易接入时间与网络

**已确认**：等程序搭建完毕后再接入；本期不阻塞 11.12 demo。

**为什么重要**：决定是否现在做 SSO、是否部署政务外网、是否影响 MVP。

**材料事实**：粤政易支持 WEB/H5/微信小程序；只有政务外网部署才能对接 SSO 等公共能力；暂无测试账号，需向省申请。

**剩余需要回答**：
1. 后续部署在互联网、政务外网，还是市云平台？
2. 是否必须单点登录/统一待办/消息推送？
3. 谁负责申请测试账号/网络策略/可信域名？大概多久？
4. 等保级别（二级/三级）与信创要求？

**已确认**：程序搭建完再接入粤政易；11.12 先做本地账号/模拟登录 + 原生小程序；架构预留 `AuthProvider`。若后续必须接入，需要把合规排期前置并接受外部依赖。

### Q-06 截止时间/验收/资源

**已确认**：11.12 前完成初步 demo + 技术文档 + 开发必要支出评估；验收人/标准/资源待确认。

**为什么重要**：决定范围砍到什么程度、是否能承诺日期。

**剩余需要回答**：
1. 11.12 验收由谁做？标准是什么（功能清单/数据准确/演示效果）？
2. demo 是本地演示即可，还是需要公网链接？服务器/域名/小程序账号谁提供？
3. 预算（模型调用、服务器、测评）范围？数据员/管理员/对接人是谁？

**建议**：11.12 先交“最小可演示闭环”；后续上线时间按反馈与合规排期，不承诺具体上线日期。

## 2. 非阻塞问题

### Q-07 等保级别

- 指引正文：联调测试要求“等保二级（或以上）”。
- 上线资料/附录：安全测试报告“须具备等保三级（或以上）”。
- **建议**：向政数部门书面确认；开发按三级控制预留（审计、权限、加密、日志），但不宣称已过等保。

### Q-08 数据库/信创

- 是否必须国产数据库（达梦/金仓）、国产 OS、ARM64？
- **建议**：11.12 用 SQLite；生产用 PostgreSQL；SQLAlchemy 避免 PG 特有语法；在 B-003 后做一次金仓/达梦适配 spike（如果确定要信创）。

### Q-09 部署资源

- 市云平台/信创云/自购服务器？域名/HTTPS/备案？
- **建议**：11.12 先本地进程演示；如需公网，一台服务器 + HTTPS + 域名白名单；Docker 后置。

### Q-10 后台角色/权限

- 谁可以导入/修改/发布？是否需要审核？
- **建议**：admin/editor/viewer；写操作审计；发布流程 P1。

### Q-11 图表/大屏

- 需要哪些图表？地图？排名？对比？导出？大屏？
- **建议**：先柱/条/饼/表；有多年数据再加折线；地图需要 GeoJSON，后置。

### Q-12 数据口径

- 空值含义？单位是否统一？统计口径（常住人口/户籍人口、GDP 年份）？
- 玉滘镇/玉窖镇哪个是标准名？经开区/生态城是否作为镇街展示？
- **建议**：空值=无数据；单位以指标为准；别名表；需求方给书面口径。
- **对外问法**：见 [17-outreach-copy.md](17-outreach-copy.md) §1 的第一条（已写成可直接发的话）。

### Q-13 AI 要求

- 是否允许“分析/建议”，还是只答数据事实？
- 准确率/引用/拒答要求？
- **建议**：只答数据事实 + 引用；分析建议标注“仅供参考”；无数据拒答；50 题评测。

### Q-14 品牌/UI

- 是否有政府视觉规范/Logo/图标/字号要求？
- **建议**：简洁政务风；先功能后视觉；图标按粤政易规范后补。

### Q-15 运维

- 谁更新数据？谁备份？故障联系谁？SLA？
- **建议**：需求方指定数据员/管理员；每日备份；故障联系人写入交接文档。

### Q-16 公众开放

- 是否需要公众访问/开放数据 API？
- **建议**：本期不做公开 API；公众访问待 Q-01 确认。

### Q-17 多语言/无障碍

- 是否需要粤语/英语/无障碍？
- **建议**：简体中文；基础无障碍（字号/对比度）后置。

## 3. 如果暂时没有答案：默认假设

6. **数据库**：PostgreSQL 16；信创适配后置。
7. **图表**：柱/条/饼/表；折线待多年数据；地图后置。
8. **权限**：admin/editor/viewer；写操作审计。
9. **验收**：先按 `02-goals.md` 的“最小成功”执行；需求方确认后再调整。
