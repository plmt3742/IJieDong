## 9. 关键发现

1. **数据是模板不是数据**：xls 的 `数据值` 列全空；不能据此验收“数据准确”，只能验收导入/展示能力。
2. **区域结构**：1 个区 + 15 个镇街（含揭东经济开发区、揭东中德金属生态城）+ 211 个村居 = 227。
3. **指标结构**：15 个指标 = 2 个文本 + 13 个数值；镇街/村居适用指标不同；数据稀疏。
4. **名称不一致**：镇街列表为“玉滘镇”，村居前缀为“玉窖镇”；必须做别名映射，不能模糊匹配。
5. **粤政易支持微信小程序/H5/WEB**，但仅在政务外网部署时才能用 SSO 等公共能力；平台仅限非密/非敏感数据。
6. **等保级别表述不一致**：指引正文写二级，上线资料/附录写三级；需向政数部门确认，架构按更严的三级控制预留。
7. **无粤政易测试账号**：需向省申请；接入周期外部不可控。
8. **需求方未给用户对象/数据来源/年份范围/LLM 部署/截止时间**：这些是当前最大不确定性。

## 10. 决策与假设

| 决策/假设 | 理由 | 影响 | 记录 |
|---|---|---|---|
| 移动端用 uni-app（Vue3+TS），同时构建微信小程序 + H5 | 粤政易支持 H5/微信小程序；单人维护一套代码 | 小程序/H5 共用页面；需验证 ECharts 小程序适配 | ADR-001 |
| Web 后台用 Vue3 + Element Plus | 数据管理场景成熟、中文资料多、与 uni-app 同生态 | 与小程序共享 TS 类型/图表 spec | ADR-001 |
| 后端 Python 3.13 + FastAPI | LLM/数据处理生态好；单人开发效率高 | 需处理 async/sync 边界；信创需验证 | ADR-001 |
| 数据用 PostgreSQL 16 | 开发/演示统一；SQLAlchemy 可移植 | 生产国产库需适配 | ADR-001/002 |
| 数据模型用规范化区域/指标/值，不用宽表 | 指标/年份扩展、稀疏数据、审计 | 查询需 join；需索引 | ADR-002 |
| Agent 只调用只读工具，不生成 SQL/JS | 安全、可测试、可解释 | 灵活性受限；新问题需加工具 | ADR-003 |
| 图表用 ChartSpec，不让 LLM 出 ECharts option | 可校验、可跨端渲染 | 图表类型受模板限制 | ADR-003 |
| MVP 先本地/互联网演示，粤政易后置 | 合规周期不可控 | 需预留 SSO/政务外网/ARM64 | ADR-004 |
| xls 模板中的空值不当作 0 | 避免错误统计 | 图表/排名需处理空值 | 05/04-data-catalog |
