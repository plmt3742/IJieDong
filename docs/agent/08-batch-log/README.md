# 批次开发记录

> 目的：让未来的人/agent 知道**每一批做了什么、为什么、怎么验证、留下什么**。不是聊天记录，也不是流水账。

## 1. 什么时候写

- 每个开发批次开始前：复制模板，写目标/范围/验收。
- 批次进行中：记录关键动作、决策、阻塞（不必逐条工具调用）。
- 批次结束后：补验证证据、文档同步、下一步，改状态。

## 2. 命名与状态

- 文件名：`B-<三位编号>-<slug>.md`，例如 `B-002-scaffold.md`。
- 编号连续；不要复用/跳号。
- 状态：`PLANNED` / `DOING` / `DONE` / `BLOCKED` / `CANCELLED`。
- 一个批次对应 0.5–2 天；超过就拆。

## 3. 记录规则

1. **只记可复核的事实**：改了哪些文件、跑了什么命令、结果如何。
2. **不粘贴大段日志/聊天**：命令输出只留关键行；完整日志放 CI/本地，不入库。
3. **决策要写“为什么”**：尤其是与文档/需求冲突时的取舍。
4. **验证要有证据**：测试通过、构建成功、截图/路径、数据计数。
5. **不记录密钥/真实敏感数据**：示例用脱敏/演示数据。
6. **批次结束必须更新索引 + `11-handoff.md`**。
