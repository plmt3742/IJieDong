## 2. 高风险项详解

### R-001 数据未到位

- **现实**：`i揭东小程序20261028.xls` 是采集模板，`数据值` 全空；需求方尚未提供填好的数据。
- **影响**：无法验证“数据准确”“排名正确”“图表有意义”；只能验证系统能力。
- **缓解**：
  1. 导入器严格按模板开发，支持错误报告。
  2. 用明确标注的演示数据做 UI/图表/AI 评测。
  3. 验收标准区分“系统能力”与“数据准确性”，后者依赖需求方。
  4. 在 `01-project.md` 与 `12-open-questions.md` 中保留为阻塞项。

### R-017 质量优先下的范围失控

- **现实**：11.12 交付 Demo v0；时间不是压缩质量的理由，但主路径、部署和验收窗口仍有限。
- **影响**：范围蔓延会拖垮契约、实现和演示；为了赶进度压缩质量，反而会产生半成品。
- **缓解**：
  1. 只做 `21` §3.2 的 Demo v0 子集；未来类型、最终视觉、合规划出本批。
  2. 按原子任务依赖推进；前置未完成不启动后续，未完成功能隐藏。
  3. 用确定性合成演示数据/预生成答案兜底；不接粤政易/SSO/地图。
  4. 每个闸门必须有命令输出/截图/手动路径；不靠子代理自述。

### R-003 粤政易/等保/信创

- **现实**：粤政易指引要求功能测试、安全测试、等保、信创符合性、密码评估；暂无测试账号；等保级别表述二级/三级不一致。
- **影响**：上线时间不可控；可能需要政务外网、国产库、私有化模型。
- **缓解**：
  1. MVP 不把粤政易作为前置条件；先做互联网/本地演示。
  2. 架构预留：AuthProvider、ARM64 镜像、可替换数据库、LLM 适配层。
  3. 需求方尽早启动申请；开发侧准备材料清单。
  4. 不承诺具体上线日期，只承诺“开发侧准备度”。

### R-007 LLM 幻觉

- **现实**：政府数据问题对数字准确性要求高；模型容易把“没有数据”编成“0”或错误排名。
- **缓解**：
  1. LLM 只能通过白名单工具取数；工具返回结构化结果。
  2. 最终答案必须带 `citations`；前端展示“指标/区域/年份”。
  3. 无数据时强制返回“当前数据没有该指标/年份”，不补 0。
  4. 50 题评测集；数字正确率 < 95% 不发布。
  5. 高风险问题（排名、对比）由后端计算，不让模型算术。

### R-011 安全

- **重点**：管理端越权、Excel 解析、AI 输出 XSS、密钥泄露、SQL 注入。
- **缓解**：
  1. 所有管理端接口按角色校验；不做“前端隐藏按钮”式权限。
  2. Excel 只解析不上传执行；限制大小/行数；临时文件隔离。
  3. AI 返回 Markdown，前端清洗；不渲染原始 HTML。
  4. 密钥只在服务端 `.env`；日志脱敏；仓库 secret scanning（P1）。
  5. 所有查询参数化；LLM 不生成 SQL。

## 3. 实现注意事项

| 领域 | 注意事项 |
|---|---|
| 数据 | 空值 ≠ 0；文本指标不参与数值图表；村居父级要校验；玉滘/玉窖用别名 |
| 导入 | 默认 atomic；错误报告含行号/列/建议；重复导入 upsert；限制 5000 行 |
| API | 统一错误码；分页上限；不要暴露堆栈；request_id |
| AI | 最多 5 次工具调用；最多 500 行；超时 30s；输出 JSON 校验；失败重试 1 次 |
| 图表 | ChartSpec 校验；空数据跳过；饼图类别过多合并“其他”；小程序控制数据量 |
| 权限 | guest/applicant/viewer/editor/approver/admin；AI 工具按权限过滤；审计写操作 |
| 部署 | 环境变量注入；健康检查；数据库备份；HTTPS；CORS 白名单 |
| 合规 | 不宣称“已过等保”；只写“按等保要求设计/待测评”；材料由需求方盖章 |
