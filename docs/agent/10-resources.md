### 5.1 关键要求

- 平台定位：仅供处理**非密、非敏感**公文、信息和事务；严禁上传国家秘密或敏感政务信息。
- 支持形态：**WEB 网页、移动 H5、微信小程序**。
- 公共能力：工作台入口、单点登录、统一待办、群聊、消息推送、用户信息、可见人员配置。
- 网络：
  - 部署在互联网/单位局域网：只能作为工作台入口跳转，不能对接省政务外网 API/公共能力。
  - 部署在政务外网：可申请网络策略，对接 SSO/用户信息/待办等。
- 上线材料：功能测试报告、安全测试报告、等保（正文写二级；上线资料/附录写三级）、信创符合性测试报告（或承诺函）、备案（如有）。
- 联调：预发布环境测试账号需向省认证申请；网络策略预发布 30 天有效。
- 移动端改造：应用图标、无权限友好页、应用简介/使用指南/维护提醒/联系电话、埋点/拨测。
- 可信域名：最多 5 个；URL 域名（含端口）必须与可信域名完全匹配；IP 同样规则。
- 平台可见性：需在粤政易管理中心配置；获取用户信息需授权，遵循最小必要。

### 5.2 对我们的影响

1. **用户对象/入口已确认**：公职人员；原生微信小程序；后续接粤政易工作台；本期不做 H5（除非粤政易强制）。
2. **SSO 不是 11.12 前置**：它依赖政务外网/测试账号；先本地账号/模拟登录。
3. **部署形态要可切换**：互联网演示 → 政务外网正式；不要让代码绑死公网。
4. **数据必须非密/非敏感**：需求方需确认数据分类。
5. **等保级别要书面确认**：二级/三级表述冲突，影响整改成本。
6. **上线材料提前准备**：功能/安全测试报告、信创/等保承诺函。
7. **粤政易后置**：已确认等程序搭建完再接入；先在 11.12 做本地 demo。

### 5.3 SSO 是什么（通俗解释）

SSO = Single Sign-On，中文叫“单点登录”。

可以把它想成**政务大厅的门禁卡**：

- 你在大厅门口刷一次卡（登录粤政易）；
- 之后去不同办公室（不同应用），不用每次再出示身份证/再登录；
- 门禁系统告诉办公室“这个人已经验证过了”，办公室只负责“他能进哪些房间”。

技术上：用户已登录粤政易，从工作台点应用时，粤政易把“已认证的身份”通过一个安全的票据/令牌带过来；应用验证票据后，建立自己的会话。用户不用在本应用再输一次账号密码。

对我们的影响：

- 好处：用户少记一套账号；人员离职/停用时，粤政易侧统一禁用；体验好。
- 前提：应用要注册到粤政易、配置可信域名、部署在能访问粤政易 API 的网络（通常政务外网）；需要测试账号/接入参数。
- 如果应用部署在互联网、无法访问省政务外网 API，通常只能做“工作台入口跳转”，不能做真正的 SSO。
- 我们的做法：11.12 先用本地账号/模拟登录；认证层抽象成 `AuthProvider`，后期按粤政易文档接 SSO，不改业务代码。
