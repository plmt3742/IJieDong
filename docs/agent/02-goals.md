# 02 · 目标与验收标准

## 1. 产品目标

| ID | 目标 | 衡量方式 | 目标值 |
|---|---|---|---|
| G-01 | 数据管理员能独立完成一次标准 Excel 导入 | 用原始模板 + 10 条错误样例走查 | 10 分钟内完成，错误行可定位 |
| G-02 | 使用者能在移动端快速找到区域指标 | 可用性走查：首页 → 区域 → 指标 → 图表 | ≤ 3 次点击，≤ 30 秒 |
| G-03 | AI 回答的数据类问题有依据 | 50 题评测集，人工核对数字与来源 | 数字正确率 ≥ 95%，引用完整率 100% |
| G-04 | AI 生成的图表可渲染且类型合理 | 50 题评测集，前端实际渲染 | ChartSpec 合法率 ≥ 98% |
| G-05 | 演示主路径稳定 | 连续走 3 次 | 3/3 成功，无阻塞错误 |
| G-06 | 粤政易接入准备度（P1） | 清单核对 | SSO/入口/友好页/图标/报告项有明确状态 |

## 2. 技术目标

| ID | 目标 | 验收方式 |

## 4. P0 功能验收

### 4.1 数据与导入

- [ ] 支持三种数据来源：Excel 导入、接口同步（预留/后续）、后台手工录入；每次导入/同步形成一批更新。
- [ ] 支持原始 xls/xlsx 模板的列：区域类型、区域名称、数据名称、数据期、单位、数据值。
- [ ] 识别 3 个区域层级；镇街含经开区/生态城；村居能解析所属镇街。
- [ ] 校验指标是否存在、单位是否匹配、数值/文本类型是否正确。
- [ ] 对“玉滘镇/玉窖镇”等名称不一致给出明确错误或别名映射。
- [ ] 导入结果有总数/成功/失败/错误明细；失败不阻断已校验通过的行（或明确事务策略）。
- [ ] 重复导入同一区域/指标/年份时执行更新而非重复插入。
- [ ] 导入记录可查；数据修改有审计日志。

### 4.2 浏览与图表

- [ ] 首页展示揭东区核心指标（至少 4 个）+ 镇街入口。
- [ ] 区域树：揭东区 → 15 个镇街 → 211 个村居；经开区/生态城无村居时不报错。
- [ ] 区域详情展示该区域适用的指标；不适用指标不显示或显示“无数据”。
- [ ] 指标详情展示数值、单位、年份、来源；支持同指标多区域对比。
- [ ] 至少支持柱状图、条形图、饼图、表格；有多年数据时折线图。
- [ ] 11.12 demo 至少支持柱状图 + 表格；图表在**原生微信小程序**可渲染；无数据时有空状态。
- [ ] 数值格式化正确（千分位、小数位、单位）；文本指标不进入数值图表。

### 4.3 AI 问答

- [ ] 11.12 使用 **DeepSeek API** 跑通至少 3 个典型问题（数值/排名/对比）。
- [ ] 支持中文自然语言提问，例如“2025 年曲溪街道的常住人口是多少？”
- [ ] 支持排名类问题，例如“2025 年哪个镇的地区生产总值最高？前 5 名是谁？”
- [ ] 支持对比类问题，例如“比较曲溪街道和云路镇的常住人口”。
- [ ] 支持区域画像类问题，例如“介绍一下玉湖镇”。
- [ ] 回答包含：结论、数据表/图表、指标/区域/年份依据。
- [ ] 数据不存在时明确说“当前数据没有该指标/年份”，不编造。
- [ ] 问题超出数据范围时拒答或引导到可用指标。
- [ ] 每次调用记录：问题、工具调用、耗时、模型、token、结果状态。
- [ ] 不在前端暴露模型 Key；不执行模型生成的 SQL/JS。

### 4.4 后台

- [ ] 登录/退出；未登录访问受保护页面跳转登录。
- [ ] 数据列表支持按区域、指标、年份筛选；分页。
- [ ] 单条数据可编辑；保存前校验；保存后审计。
- [ ] 导入页可上传、查看进度/结果、下载错误报告。
- [ ] 审计日志可按用户/动作/时间筛选（最小可用）。
- [ ] 角色覆盖 guest/applicant/viewer/editor/approver/admin（见 `05` §9 与 `23`）。

## 5. 非功能验收

- [ ] 密钥只在 `.env`/服务器环境变量；仓库无密钥。
- [ ] 密码使用强哈希；JWT 有过期时间；401 自动跳登录。
- [ ] CORS 只允许配置的前端域名；错误响应不泄露堆栈。
- [ ] 上传文件类型/大小校验；Excel 解析有超时/行数上限。
- [ ] 所有管理端写操作有审计日志。
- [ ] AI 工具只读；参数白名单；最多工具调用次数；最大返回行数。
- [ ] 日志包含 request_id；AI 调用记录模型、耗时、token、状态。
- [ ] 原生微信小程序在开发者工具/常见机型可用；弱网有 loading/重试。
- [ ] 断网/超时/模型额度不足时有可理解提示，不白屏。
- [ ] 数据库备份/恢复步骤有文档（演示环境至少每日备份）。

## 7. Definition of Done（单个任务）

任务只有满足以下条件才算 `DONE`：

1. 代码实现并可本地运行。
2. 有必要的测试（后端 service/API；前端关键组件/E2E）。
3. lint/typecheck/build 通过。
4. 相关文档更新（API/数据模型/页面规范/任务状态）。
5. 自测路径有记录（命令输出、截图或演示步骤）。
6. 没有密钥、调试代码、无意义日志进入提交。
7. 批次记录已更新，交接快照已同步。

> 单人项目没有“别人 review”，但必须做**自审清单**；不能因为没人看就跳过。

## 8. 验收视角

| 验收者 | 会看什么 | 我们的准备 |
|---|---|---|
| 需求方 | 数据是否全、是否准、是否好用 | 导入报告 + 数据覆盖看板 + 走查 |
| 数据管理员 | 导入是否省事、错误是否可定位 | 模板校验 + 错误明细 + 审计 |
| 领导 | 图表是否清楚、能否直接汇报 | 统一首页总览 + 排名 + 导出（P1；不单独开发模式） |
| 政数/粤政易 | 安全、合规、网络、材料 | ADR-004 + 检查清单 + 测试报告 |
| 开发者自己 | 能否维护、能否交接 | 文档 + 批次记录 + 测试 |

## 9. 成功标准（本项目）

**最小成功**：数据管理员能导入真实数据，公职人员能在手机上浏览并看到正确图表，AI 能对 50 个典型问题给出有依据的答案和可渲染图表。

**不以此为目标**：功能数量、页面数量、模型参数、技术栈“先进性”。先保证**数据准确、闭环可用、可解释、可维护**。
