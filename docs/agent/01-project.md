# 01 · 项目定义

## 1. 背景与问题

揭东区需要把政府数据“数字化存起来、看得懂、问得出”。当前材料显示的现实是：

1. **数据分散**：区、镇街、村居三级数据以 Excel 模板收集，缺少统一的数据底座与更新机制。
2. **查询门槛高**：想知道“某镇某指标是多少/排第几”，需要翻表、对口径、再做图。
3. **展示能力弱**：现有材料只有指标目录，没有面向移动端的浏览、对比、图表能力。
4. **AI 需求明确但边界模糊**：需求方希望“问答式调数据 + 生成可视化图表”，但未说明模型、数据密级、部署方式与准确率要求。
5. **合规后置**：后期要接粤政易，涉及等保、信创、密码评估、政务外网/互联网部署选择，不能按普通 Web 项目处理。

本项目要补的是：**一个可治理、可追溯、可移动访问的数据门户，并让 AI 在受控范围内查数据、答问题、出图表。**

## 2. 目标用户（已确认方向）

> 已确认：**公职人员**使用；微信小程序后续接入粤政易工作台；粤政易等程序搭建完再接入。

| 用户 | 场景 | 关键诉求 | 优先级 |
|---|---|---|---|
| 区/镇街公职人员 | 手机查看本区/本镇指标、向上汇报 | 快、准、能截图/转发 | P0 |
| 数据管理员（区政数/业务科室） | 导入 Excel/接口/手工录入、修订数据、看审计 | 批量更新、校验、可回滚 | P0 |
| 领导/决策者（公职人员） | 看总览、排名、对比，导出汇报卡 | 一屏看懂、图表清晰；复用统一页面，不单独开发模式 | P1 |
| AI 问答使用者（公职人员） | 用自然语言问数据 | 答案有依据、图表可解释 | P0 |
| 公众 | 查看公开数据 | 无需登录/轻登录 | P2（本期不做） |

> 领导/决策者不是独立入口或独立页面；不单独开发“领导模式”。其需求通过统一首页总览、指标详情、排名/对比和导出汇报卡满足。

**入口规划**：

1. **近期（11.12 demo）**：原生微信小程序 + Web 后台；本地/测试号运行。
2. **后期**：微信小程序接入粤政易工作台；是否再用粤政易 SSO 由接入方案决定。
3. **不做**：本期不做公众版/独立 App；公众访问列入 P2。

## 3. 价值主张

> **揭东数据，一查就有；问一句，就能出图。**

- **对管理者**：从“翻 Excel、找人要数”变成“打开就能看、能对比、能问”。
- **对数据员**：一套模板导入、自动校验、错误可定位，数据变更可追溯。
- **对领导**：通过统一首页总览、镇街排名、指标对比和导出汇报卡满足汇报需求；不单独开发“领导模式”。
- **对 AI**：不是“让模型编数字”，而是“模型调用受控工具查库，答案带数据依据”。

| ID | 用户故事 | 优先级 |
|---|---|---|

| US-03 | 作为公职人员，我可以按“区 → 镇街 → 村居”浏览区域，并查看指标值 | P0 |

| US-05 | 作为使用者，我可以用自然语言问“2025 年哪个镇 GDP 最高”，得到答案 + 图表 + 数据来源 | P0 |

## 5. 范围

> 2026-11-10 更新：11.12 Demo v0 的 P0 以 [15-demo-plan-1112.md](15-demo-plan-1112.md) §11 为准，新增认证/申请/审批、游客模式、PNG/PDF/XLSX/CSV 四格式导出、Web 后台可视化；原 P1 中的“导出/申请审批/更完整角色”已前移到 11.12。

### P0（MVP / 可演示、可试用）

1. **数据底座**：区域、指标、数据值三张核心表；当前支持 2025 年、15 个指标、227 个区域；模型支持后续扩展。
2. **三种数据来源**：Excel 导入（优先）、接口同步（预留/后续）、后台手工录入；每次导入/同步形成一批更新。
3. **数据管理后台（最小）**：登录、数据列表/筛选、单条编辑、导入记录、审计日志。
4. **移动端（原生微信小程序）**：首页总览、区域树浏览、区域详情、指标详情、基础图表。
5. **AI 问答（受控）**：DeepSeek API + 工具查询 → 答案 + ChartSpec + 数据依据；支持追问；记录问答日志。
6. **图表**：柱状图、条形图、饼图、表格；有多年数据时支持折线图。
7. **11.12 demo 运行方式**：用户小服务器部署 + SQLite；微信小程序实测；Web 后台可视化；不强制 Docker。
8. **安全底线**：服务端保存 LLM Key；JWT；基础 RBAC；输入校验；审计日志；不在前端暴露密钥。

### P1（P0 稳定后）

- 多年数据与趋势图、同比/环比。
- 区域排名、批量对比、收藏/常用图表。
- 地图可视化（需要揭东区/镇街 GeoJSON）。
- 导出 PNG/Excel；汇报模式/大屏模式。
- 粤政易工作台入口 + 单点登录 + 无权限友好页 + 图标规范。
- 更完整的数据审核/发布流程、角色权限。
- 问答评测集与准确率看板。

### P2（明确不做进本期）

- 模型训练/微调、强化学习。
- 完整 BI 自助分析（拖拽式报表、任意维度建模）。
- 实时数据流/物联网接入。
- 多租户 SaaS、对外开放 API 平台。
- 复杂知识图谱、预测性分析。
- 无认证的完全公开数据门户。

### 非目标（Non-goals）

- **不做“AI 直接写 SQL 查库”**：只允许受控只读工具，避免注入、越权、幻觉。
- **不做“任意代码生成图表”**：LLM 只产出受约束的 ChartSpec，前端用固定渲染器。
- **不做完整数据中台**：本期只覆盖揭东区/镇街/村居的指标数据。
- **不替代粤治慧**：如需求方已有粤治慧数据能力，优先对接而不是重复建设。
- **不做多人协作功能**：个人开发、单管理员起步。

## 8. 开发体量估算

> 估算单位：**人天**；假设开发者熟悉 Vue/Python、有 AI 辅助、数据干净、无地图/无 SSO/无大屏。实际以批次复盘修正。

| 模块 | P0 最小 | P0 完整 | P1 追加 | 说明 |
|---|---:|---:|---:|---|
| 文档/架构/批次管理 | 3 | 4 | 1 | 本批已投入 |
| 工程脚手架 + CI | 5 | 7 | 2 | monorepo、三端脚手架、lint、测试、健康检查、CI |
| 数据模型 + 迁移 + 种子 | 4 | 6 | 2 | 区域/指标/值/来源/审计 |
| Excel 导入 + 校验 | 5 | 7 | 2 | 模板解析、别名、错误报告 |
| 后端 API + 认证 + RBAC | 5 | 8 | 3 | 管理端 + 移动端 + AI 接口 |
| Web 后台 | 7 | 11 | 4 | 登录、数据管理、导入、审计、图表预览 |
| 原生微信小程序 | 8 | 12 | 5 | 浏览、详情、图表、问答、适配 |
| 图表与 ChartSpec | 3 | 5 | 3 | 柱/条/饼/表/折线；地图另计 |
| AI Agent | 6 | 9 | 4 | 工具、Prompt、校验、日志、评测 |
| 部署/演示环境 | 3 | 5 | 2 | Compose、Nginx、HTTPS、种子 |
| 测试/安全/验收 | 4 | 7 | 3 | 单测、E2E、权限、审计、压测 |
| **合计** | **53** | **81** | **31** | 不含粤政易与合规认证 |

> 表中“P0 最小”是**可试用 MVP**（含后台、移动端、AI、部署、测试），合计 53 人天；“P0 完整”含更多边界/测试/打磨，81 人天。若只做**演示闭环**（导入 + 浏览 + 3 类图表 + 基础问答，不含完整后台/测试/部署），可压缩到 **25–35 人天**；对应全职 5–7 周、每天 4 小时约 10–14 周。

**粤政易/合规另计**：

| 项 | 开发人天 | 外部周期 | 说明 |
|---|---:|---|---|
| 粤政易 SSO + 工作台入口 + 友好页 + 图标 | 5–8 | 1–2 月 | 需政务外网、测试账号、接入参数 |
| 等保测评 | 2–4 | 1–3 月 | 整改、测评机构、报告 |
| 信创符合性测试 | 2–5 | 1–3 月 | 国产 CPU/OS/DB 适配 |
| 密码评估 | 1–3 | 1–2 月 | 如涉及密码应用 |
| 功能/安全测试报告 | 2–3 | 2–4 周 | 第三方或开发商盖章 |

**11.12 初步 demo**：按“演示闭环”估算 **10–15 人天**（6 个自然日、每天 8–10 小时、AI 辅助），只做导入 + 小程序浏览 + 指标图表 + 基础 AI 问答；不含粤政易/SSO/地图/完整后台/完整测试。详见 [15-demo-plan-1112.md](15-demo-plan-1112.md)。

**结论**：先做 **11.12 演示闭环**验证价值，再决定是否投入完整 P0/P1 与合规。不要一开始就按“完整政府平台”排期。

## 9. 关键假设

1. 需求方最终能提供**填好的数据**或明确的数据接口；否则系统只能做“数据采集 + 展示”，价值会打折。
2. 数据为**非密、非敏感**的统计/介绍类数据，符合粤政易平台准入要求；DeepSeek 公有云可用（待确认）。
3. 允许在开发/演示阶段使用 DeepSeek 公有云 API；正式环境可按要求切换私有化/政务云模型。
4. 原生微信小程序是主入口；后期接入粤政易工作台；粤政易不是 11.12 demo 的前置条件。
5. 首期不需要地图、不需要实时数据、不需要复杂 BI；H5 仅在粤政易强制时补。
6. 单人开发可按批次持续推进；外部合规与数据到位时间不可控。
