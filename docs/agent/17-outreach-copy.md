# 17 · 对外对接文案（通俗版）

> 用法：一次只发一组问题；用“第一、第二、第三”罗列；不解释系统原理；给对方选项；把回答记录到 `12-open-questions.md`。
> 原则：**问“要什么/以哪个为准/谁来提供”，不问“你们系统怎么跑”。**

## 1. 数据内容与口径

> 发给：需求方/数据提供人/业务科室

第一，镇街名称写的是“玉滘镇”，村居前面写的是“玉窖镇”，这两个写法不一样。请问对外统一用哪个？

第二，现在 Excel 里的“数据值”都是空的。后续是由你们填好 Excel 给我们，还是我们做一个录入页面，由你们在页面上填？

第三，数据大概多久更新一次？是每年更新、每季度更新，还是不定期更新？

第四，除了现在这张表里的 15 项数据，后续还会增加哪些数据？有没有一个清单或样例？

第五，现在表里只有 2025 年的数据。后续会不会补以前年份的数据？大概从哪一年开始？

第六，这些数据里有没有不能对外公开、或者不能让外部大模型处理的内容？如果有，是哪些？

第七，能不能先给我们一个镇街或一个村居的**填好的样例数据**？我们先用它把导入和图表跑通。

第八，数据这块以后谁负责对接？请给一个联系人（姓名/电话/微信）。

## 2. 用户与入口

> 发给：需求方/项目负责人

第一，这个小程序是不是只给公职人员使用？普通群众需不需要用？

第二，后续是从粤政易工作台点进来使用，还是微信里也能直接打开？两个入口都要，还是只要粤政易？

第三，用户进入小程序时，要不要登录？如果登录，是用微信登录、手机号登录，还是直接用粤政易账号登录？

第四，后台管理系统大概有几个人用？分别负责什么（看数据/改数据/导入数据/审核）？

## 3. 粤政易、网络与合规

> 发给：需求方/政数部门

第一，粤政易接入大概安排在什么时候？是程序做完之后再接，还是现在就要开始准备？

第二，程序最终放在哪里运行？是互联网、政务外网，还是市里的云平台？

第三，从粤政易工作台点进来时，要不要“一次登录、直接进入”（也就是不用再输账号密码）？如果需要，我们按这个方向预留。

> 备注：这就是 SSO（单点登录）。用户已经在粤政易登录过，点应用时平台把身份带过来，应用不用再登录一次。

第四，粤政易的测试账号、测试环境大概怎么申请？需要谁去申请？大概要多久？

第五，等保要做二级还是三级？我们看到的材料里，有的地方写二级，有的地方写三级，需要确认一个准。

第六，有没有要求必须用国产服务器、国产操作系统、国产数据库？如果有，是哪些？

第七，公网访问需要域名和 HTTPS 吗？域名、证书、服务器由谁提供？

## 4. 大模型与数据安全

> 发给：需求方/政数部门/安全负责人

第一，我们的数据是否属于“非密、非敏感、可以发给外部大模型处理”的数据？

第二，是否允许使用 DeepSeek 的公有云服务？如果不允许，是否允许用政务云上的大模型服务？

第三，如果必须把模型放在政府自己的服务器上，现在有没有 GPU/政务云资源？没有的话，预算大概是多少？

第四，问答记录要不要保存？保存多久？谁可以查？

第五，大概有多少人用、每天大概问多少次？我们用来估算费用。

## 5. 11.12 Demo 与验收

> 发给：需求方/项目负责人

第一，11 月 12 日希望看到哪些内容？是看“能导入数据、能看图表、能问问题”，还是还要看后台管理/粤政易？

第二，11.12 的 demo 由谁来看、谁来验收？验收标准是什么？

第三，demo 是本地演示就行，还是需要一个公网链接？如果需要公网，服务器/域名/小程序账号由谁提供？

第四，11.12 之前，数据样例、DeepSeek API Key、小程序 AppID 最晚什么时候能给到我们？

## 8. 提问注意事项

1. **一次只问一组**：不要一条消息塞 20 个问题。
2. **给选项**：对方更容易回答“A 还是 B”，而不是开放式描述。
3. **不解释架构**：不说“前后端/数据库/接口协议”，说“数据怎么给我们/放在哪里/谁登录”。
4. **确认责任人**：每个问题尽量落到“谁提供/谁决定/什么时候”。
5. **记录原话**：对方回答后，把结论写进 `12-open-questions.md`，不要只留在聊天里。
6. **不承诺**：对方问“多久做完/能不能过等保”，只回答“我们按计划推进/需要测评机构确认”，不拍胸脯。
