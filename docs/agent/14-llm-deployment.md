# 14 · LLM 部署方案详解

> 先给结论：**11.12 演示用 DeepSeek 公有云 API；生产是否私有化，取决于数据密级和政务云资源。代码从现在起就做“可切换”适配层，不把 DeepSeek 写死。**

## 1. 先理解“LLM 部署”在说什么

大模型不是装在小程序里的。用户问一句话，系统要把问题发给一个“模型服务”，模型返回答案。这个“模型服务放在哪里、谁运维、数据经过谁”，就是 LLM 部署方案。

常见四种：

1. **公有云 API**：模型在厂商机房，你按调用量付费。
2. **政务云/专属云 API**：模型在云厂商的隔离环境，数据不进入公共池。
3. **私有化部署**：模型跑在你自己/政府的服务器/GPU 上，数据不出内网。
4. **混合**：演示/非敏感用公有云，正式/敏感用私有化。

## 2. 四种方案对比

| 维度 | 公有云 API（DeepSeek 官方） | 政务云/专属云 API | 私有化部署（vLLM/Ollama） | 混合 |
|---|---|---|---|---|
| 数据是否出网 | 是，发给厂商 | 是，但在云隔离环境 | 否，留在内网/政务云 | 按数据分级路由 |
| 上线速度 | 最快，几小时 | 中，需开通/审批 | 慢，需 GPU/环境/模型 | 中 |
| 成本 | 按 token，低 | 按 token/资源，中 | GPU/运维，高 | 组合 |
| 模型质量 | 厂商最新模型 | 受云厂商模型库限制 | 取决于开源模型/GPU | 组合 |
| 运维 | 厂商 | 云厂商 | 自己/政务云团队 | 组合 |
| 合规 | 需确认数据条款 | 更适合政务 | 最可控 | 按分级 |
| 适合 | demo、非敏感数据 | 政务正式、非密 | 敏感/要求数据不出网 | 分阶段 |

## 3. DeepSeek 公有云 API（当前初步决策）

### 3.1 是什么

- DeepSeek 提供 OpenAI 兼容接口；我们只需配置 `base_url`、`api_key`、`model`。
- 调用发生在**后端**，小程序/后台永远不接触 Key。
- 支持对话、工具调用（以官方当前能力为准）；适合“模型选工具、后端查数据、模型组织答案”。

### 3.2 优点

- 接入最快：今天申请 Key，今天就能跑通。
- 成本低：按 token 计费，demo 阶段通常几十到几百元/月量级（以官网价格为准）。
- 中文/政务表达好；开发者生态成熟。
- 不需要 GPU/运维。

### 3.3 风险/限制

| 风险 | 说明 | 缓解 |
|---|---|---|
| 数据出网 | 问题、上下文、工具结果会发给 DeepSeek | 只发必要字段；脱敏；确认数据非密/非敏感 |
| 数据使用条款 | 需阅读并确认厂商的数据使用/保留政策 | 由需求方/法务确认；必要时换专属云/私有化 |
| 服务可用性 | 限流/故障/额度不足 | 超时/重试/缓存/备用模型/降级 |
| 模型更新 | 模型名/能力可能变化 | 配置化模型名；评测回归 |
| 合规审批 | 政府数据可能要求“不出网” | 生产切私有化/政务云 |

### 3.4 成本估算方式

按 token 计费，公式：

```text
月成本 ≈ 月提问次数 × (输入 token 数 × 输入单价 + 输出 token 数 × 输出单价)
```

示例（仅用于量级判断，价格以官网为准）：

- 每天 100 次问答，每次输入 2,000 tokens、输出 500 tokens。
- 月输入 6,000,000 tokens、输出 1,500,000 tokens。
- 按常见低价区间估算，月成本通常在**几十元到几百元人民币**；高频/长上下文会上升。

> 不要用“包月无限量”思维；设置每用户/每日限额、最大上下文、缓存常见问题。

## 4. 政务云/专属云 API

- 例如政数部门指定的政务云模型服务、运营商/云厂商的专属实例。
- 优点：数据在政务云/隔离环境，合规性更好；有合同/发票/运维支持。
- 缺点：开通/审批周期；模型选择少；价格/性能需测试。
- 适合：正式环境、非密但要求数据不出公网的数据。

## 5. 私有化部署

### 5.1 是什么

把开源模型（DeepSeek、Qwen 等）部署到自己的 GPU 服务器/政务云，使用 vLLM、SGLang、Ollama 等推理框架，暴露 OpenAI 兼容接口。我们的后端只改 `base_url`/`model`，业务代码不变。

### 5.2 需要什么

| 项 | 说明 |
|---|---|
| GPU | 7B–14B 模型通常需 16–24GB 显存；更大模型需多卡/更高显存 |
| 服务器/操作系统 | Linux；政务云/信创环境需适配 |
| 推理框架 | vLLM（吞吐好）、Ollama（简单）、SGLang（高性能） |
| 模型文件 | 开源权重；需确认许可证 |
| 运维 | 启停、监控、显存、并发、升级、安全 |
| 网络 | 政务外网/内网；不暴露公网 |

### 5.3 成本量级（估算，需询价）

| 方式 | 成本 |
|---|---|
| GPU 云服务器租用 | 约 2,000–10,000 元/月/卡（取决于型号/区域） |
| 采购 GPU 服务器 | 约 5 万–20 万元+（取决于显卡/整机） |
| 运维人力 | 需要懂推理框架/GPU 的人 |
| 模型/框架 | 开源免费，但许可证/合规需确认 |

### 5.4 优点/缺点

- 优点：数据不出内网；可控；可离线；长期高频调用可能更划算。
- 缺点：前期成本高；模型质量取决于开源模型/GPU；运维复杂；升级慢。

## 6. 混合方案（推荐的生产路径）

```text
非敏感/演示问题 → 公有云 DeepSeek API
敏感/正式数据   → 政务云/私有化模型
```

实现方式：

- 配置多个 `LLMProvider`：`deepseek`、`gov-cloud`、`private-vllm`。
- 按环境变量/数据分级/用户角色路由；默认只启用一个，避免复杂。
- 同一套 Prompt/工具/ChartSpec；只换模型端点。
- 评测集在切换模型后必须重跑。

## 7. 安全底线（无论哪种方案）

| 项 | 要求 |
|---|---|
| Key | 只在服务端 `.env`/密钥管理；不进前端/仓库/日志 |
| 数据最小化 | 只发问题所需字段；不把整库/整表塞给模型 |
| 脱敏 | 人名/手机号/内部标识按需脱敏；本期数据以统计为主 |
| 工具白名单 | 模型只能调用只读工具；不生成 SQL/JS |
| 超时/重试 | 10–30s 超时；重试 1 次；失败有可读提示 |
| 限流 | 按用户/IP/会话限制；防刷 |
| 日志 | 记录模型/耗时/token/工具调用；不记录 Key/完整敏感数据 |
| 审计 | 问答记录可查；支持追责/纠错 |
| 降级 | 模型不可用时：缓存答案/表格/“请稍后再试” |

## 8. 建议决策树

```text
数据是否非密、非敏感，且允许发送到公有云？
├─ 是 → 11.12 demo 用 DeepSeek API；生产可继续用或换政务云
└─ 否 → 是否已有政务云/GPU 资源？
        ├─ 是 → 私有化 vLLM/Ollama + 开源模型
        └─ 否 → 先申请资源/预算；demo 用脱敏数据 + DeepSeek，明确标注“非真实数据”
```

## 9. 需要向需求方确认的问题（通俗版）

1. 我们的数据是否属于“非密、非敏感、可以发给外部大模型处理”的数据？
2. 是否允许使用 DeepSeek 的公有云服务？如果不允许，是否允许使用政务云上的模型服务？
3. 如果必须私有化，政府是否已有 GPU/政务云资源？没有的话，预算大概多少？
4. 问答内容是否需要留存/审计？留存多久？
5. 每月大概多少人用、每天大概多少次问答？用于估算成本。

## 10. 本项目落地方式

- 环境变量：`LLM_PROVIDER=deepseek`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT`。
- 代码：`app/ai/client.py` 只依赖 OpenAI 兼容接口；不 import DeepSeek 专有 SDK。
- 工具：`list_regions`、`list_indicators`、`get_indicator_values`、`rank_regions`、`compare_regions`、`get_region_profile`、`build_chart`。
- 输出：`answer_markdown` + `chart_spec` + `citations`；Pydantic/ChartSpec 校验。
- 评测：50 题；记录数字正确率、引用完整率、ChartSpec 合法率、延迟、token。
- 11.12：DeepSeek API + 演示数据；不接粤政易 SSO/政务外网。
